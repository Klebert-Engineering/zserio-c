## Statement

The runtime library and any code generated by the zserio-c generator
SHALL NOT contain direct or indirect recursive function calls. Schema
constructs that describe nested or recursive types SHALL be encoded by
explicit, bounded iteration using an externally provided workspace
buffer.

## Rationale

Recursive code makes worst-case stack usage hard to bound, which directly
threatens the safety case. MISRA C:2012 Rule 17.2 prohibits recursion.
For zserio specifically, schema trees can in principle be deeply nested
(structs of structs, optionals of arrays of structs, etc.), so the
generator must produce iterative encode/decode logic with the depth
budget exposed in the generated API.

## Verification

- cppcheck `--addon=misra` enforces Rule 17.2 (compile-time call-graph
  detection).
- Generator unit tests assert that for a representative deeply-nested
  schema, no generated function calls itself directly or transitively.

## Notes

- The generator emits per-schema metadata reporting the maximum nesting
  depth and the workspace size required at that depth, so callers can
  size buffers statically.
- Templates that rely on recursion in the *template engine* are fine; this
  rule constrains the *emitted* C code only.
