title: Bounded decode depth
type: safety

## Statement

The runtime library SHALL NOT contain direct or indirect recursive
function calls. Code generated by the zserio-c generator MAY descend
through nested compound types by direct calls, but every such descent
SHALL be guarded by a runtime depth gate on the bitstream reader: the
decode SHALL fail with `ZSERIO_ERR_MAX_DEPTH_EXCEEDED` — before the C
stack is at risk — once nesting exceeds a caller-tunable ceiling. The
ceiling SHALL have a documented default and SHALL be adjustable per
reader so integrators can size worst-case stack use for their target
(worst case = ceiling × per-level frame cost, with the per-level
frame cost bounded by the stack gate).

## Rationale

Unbounded recursion makes worst-case stack usage impossible to bound,
which directly threatens the safety case; zserio schemas permit
self-referential types, so a decoder's nesting depth is governed by
the *input* — on the untrusted-decode path, by an attacker. A
runtime depth gate bounds it deterministically: integrators derive
their stack budget from `max_depth × frame ceiling` instead of from
schema analysis alone, and crafted deeply-nested input is rejected
with a status code instead of faulting (hazard H-09).

## Verification

- Runtime: cppcheck `--addon=misra` enforces Rule 17.2 on
  `runtime/src/*` (compile-time call-graph detection) — the runtime
  itself stays recursion-free.
- Generated code: unit tests drive recursive schemas with
  adversarially deep input and assert the decode fails with
  `ZSERIO_ERR_MAX_DEPTH_EXCEEDED` at the configured ceiling
  (`tests/runtime/test_decode_hardening.c`, `test_bitstream.c`).
- Frame ceilings: `tools/measure_stack_usage.py --strict`
  (≤256 B/frame) bounds the per-level cost the ceiling multiplies.

## Notes

- Default ceiling: 1024; per-reader override via
  `zserio_bitstream_reader_set_max_depth()`. Generated compound /
  choice readers bracket their body with
  `zserio_bitstream_reader_enter` / `_leave`.
- A depth-gated descent was chosen over the worklist alternative:
  it keeps the read descent allocation-free and the hot path
  simple, while the safety goal — statically boundable worst-case
  stack on attacker-controlled input — is met by the gate.
- MISRA C:2012 Rule 17.2 (no recursion) continues to apply to the
  runtime library unconditionally. For generated code the rule is
  satisfied at the system level by the depth gate; the cppcheck gate
  on generated output covers the remaining rule set.
- Templates that rely on recursion in the *generator's own
  implementation* are a build-time tool concern, bounded separately
  (`ZSP_MAX_PARSE_DEPTH`, `ZSP_MAX_TEMPLATE_DEPTH`); this requirement
  constrains the *emitted* C code and the runtime only.
