## Statement

The runtime library and any code generated by the zserio-c generator
SHALL NOT use `setjmp`, `longjmp`, `_setjmp`, `_longjmp`, `siglongjmp`,
`sigsetjmp`, or any equivalent non-local control transfer. Errors SHALL
propagate by returning a `zserio_status_t` value and writing outputs only
when the returned status is `ZSERIO_OK`.

## Rationale

Non-local jumps are explicitly forbidden by MISRA C:2012 Rule 21.4 and
make data-flow analysis intractable for the safety case. Status-code
propagation forces the call stack to be linear and inspectable, and
makes it trivially analyzable that no caller proceeds with invalid
output state.

## Verification

- cppcheck `--addon=misra` enforces Rule 21.4.
- Belt-and-braces: a CI grep step rejects any use of the forbidden symbols
  in `runtime/` and generated code.

## Notes

- This is also why we do not exception-translate at any boundary: there
  is no exception layer to translate.
- `goto` is permitted only for forward jumps to a single function-local
  cleanup label, in line with MISRA C:2012 Rule 15.1's deviation pattern.
  This will be tracked under `docs/misra-deviations/` if used.
