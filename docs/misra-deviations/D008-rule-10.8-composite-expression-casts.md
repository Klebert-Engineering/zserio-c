## Statement of the rule (paraphrased)

Rule 10.8 requires that the value of a composite expression not be
cast to a different essential type category or to a wider essential
type.

## Where it is deviated

Six sites, verified against cppcheck 2.21 by removing the suppression
and re-running `tools/run_misra.sh`. Two shapes:

**(a) Widening cast of an unsigned composite expression** — forcing
the bit-manipulation arithmetic into 64-bit before a shift or mask:

- `runtime/src/bitstream.c:245` —
  `(uint64_t)1U << (uint64_t)(num_bits - 1U)` (sign-bit position for
  sign extension)
- `runtime/src/bitstream.c:411` —
  `(value >> shift_num) & (uint64_t)(0xFFU >> bits_used)` (partial-byte
  mask on the writer path)
- `runtime/src/bitstream.c:463` (second finding on the line) —
  `(uint64_t)(num_bits - 1U)` as shift amount in the range check
- `runtime/include/zserio/bitstream.h:288` — same sign-bit idiom in
  the inlined hot-path reader
- `runtime/include/zserio/primitives.h:103` — same sign-bit idiom in
  `zserio_primitives_sign_extend`

**(b) Cast changing the essential type category** — moving a value
whose non-negativity or range is established by a guarding branch
across the signed/unsigned boundary:

- `runtime/src/float.c:148` —
  `(uint32_t)((int32_t)1 - signed_exponent16)`; the enclosing branch
  guarantees `signed_exponent16 <= 0` and
  `signed_exponent16 > -(int32_t)FLOAT16_SIGNIFICAND_NUM_BITS`, so the
  composite value is in `[1, 11]`
- `runtime/src/bitstream.c:463` (first finding on the line) —
  `(int64_t)(((uint64_t)1U << (uint64_t)(num_bits - 1U)) - 1U)`; with
  `num_bits < 64` the value is at most `2^62 - 1`, well inside
  `INT64_MAX`

## Justification

Both shapes are deliberate:

- In shape (a), the cast documents that the surrounding computation is
  carried in `uint64_t`. The strictly rule-conforming spelling — cast
  each operand individually before combining
  (`(uint64_t)num_bits - 1U`) — produces identical object code but
  detaches the cast from the value it is meant to widen, hiding the
  intent the cast exists to express. Shift amounts and masks derived
  from validated `num_bits` values are the core arithmetic of the
  bitstream codec; keeping the widening visible at the composite level
  is the reviewed house idiom.
- In shape (b), the value crossing the category boundary is provably
  in range for the destination type by the immediately enclosing
  branch condition, cited per site above. The conversion is
  well-defined C99 in both directions for the input domain.

The suppression in `tools/cppcheck-suppressions.txt` is rule-wide
rather than file-scoped because the suppressions file is shared with
the generated-output gate (`tools/run_misra_generated.sh`), where the
same shift/mask idioms appear in files whose names are
schema-dependent and cannot be path-scoped.

## Mitigation

- Every site sits behind an explicit range validation
  (`num_bits` checked against `[1, 64]` at function entry; the
  float16 exponent branch conditions cited above). The guard and the
  cast are adjacent and reviewed together.
- The bitstream read/write paths that contain these casts are
  exercised across the full 1..64 width range by the unit suite
  (`tests/runtime/test_bitstream.c`, including randomized
  mixed-width sweeps) and end-to-end by the 183-schema xvalidation
  gate; a wrong widening or sign error surfaces as a byte
  divergence.
- The float16 subnormal path is covered by dedicated bit-pattern
  round-trip tests (`tests/runtime/test_float.c`).
- New code is expected to prefer single-operand casts where the
  intent survives; composite-level casts are accepted only with an
  adjacent range guard, checked in review.
