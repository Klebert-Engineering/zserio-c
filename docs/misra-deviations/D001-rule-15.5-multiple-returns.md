## Statement of the rule (paraphrased)

Rule 15.5 advises that a function should have a single point of exit
at the end. Each `return` statement that is not the last statement of
its function is a deviation.

## Where it is deviated

Project-wide. Every public runtime function returns
`zserio_status_t`, and the standard idiom is "validate then continue,
returning early on any error":

```c
zserio_status_t f(...) {
    if (bad_input)             return ZSERIO_ERR_INVALID_ARGUMENT;
    if (would_overflow)        return ZSERIO_ERR_BUFFER_OVERFLOW;
    /* main work */
    return ZSERIO_OK;
}
```

The `ZSERIO_TRY(...)` macro defined in `runtime/include/zserio/status.h`
also expands to `if (st != ZSERIO_OK) return st;`, generating an
early-return per call site.

Every `runtime/src/*.c` file uses this idiom. The cppcheck triage on
2026-05-08 produced ~110 `misra-c2012-15.5` findings spread across
all modules.

## Justification

The project's safety case explicitly chooses status-code error
handling over single-exit / cleanup-label patterns:

- **REQ-FS-002** forbids `setjmp` / `longjmp`, so non-local control
  flow is not available.
- The status-code idiom keeps each error path explicitly visible at
  the call site. A single-exit refactor would require a sentinel
  variable threaded through every branch and a `goto cleanup`
  pattern, which itself runs into MISRA Rule 15.1 deviations.
- The code-base is small enough to keep early-return patterns
  reviewable. Each public function fits comfortably on a screen.

The rule is **advisory**, not required, and routinely deviated in
modern C codebases that use early-return error handling.

## Mitigation

- Every public entry point has dedicated negative-path unit tests
  that verify the early-return path produces the documented status
  code without partial state mutation (REQ-FS-006 verification).
- Code review for any new function checks that error paths are
  exhaustive and that no resource is leaked between the validation
  block and the success path.
- The suppression in `tools/cppcheck-suppressions.txt` is rule-wide
  rather than file-scoped, accepting that the deviation applies
  globally; new code is expected to use the same idiom.
